# JSON to Image Converter

Command-line tool that turns an adventure-location JSON file into a **human-editable scene file**, then optionally renders a still image with Gemini.

You do **not** need a Gemini API key to compile the scene. A key is only required when you want the app to generate the PNG.

## Why there is a scene file

The source JSON describes a text-adventure location (IDs, exits, look text, game state). That is not enough to draw a picture by itself: a renderer still needs camera, light, materials, and what to show on each wall.

The converter writes that missing layer next to the original file, using the same base name:

| Input | Written alongside |
| --- | --- |
| `example_file.json` | `example_file.scene.json` |
| then, if a key is set | `example_file.small_house.png` |

`*.scene.json` is safe to edit. Change the camera, move a prop, or rewrite the `prompt` field, then run the CLI on the scene file to re-render without touching the adventure JSON.

Leave `prompt` as an empty string to rebuild it from the structured fields.

## Do you need a Gemini API key?

**Only for the image, not for the converter.**

- Scene compilation is deterministic. It reads the location JSON and fills defaults (eye-level camera at the south wall looking north, pale oak / cream cottage style, implied window from the description).
- The final still that looks like a stylized 3D interior is generated by a Gemini image model. That step needs `GEMINI_API_KEY`.
- A later 3D renderer could use the same scene file with no AI. That is not in this first version.

Create a key in [Google AI Studio](https://aistudio.google.com/apikey). Keep it out of git.

```powershell
copy .env.example .env
# put the key in .env, or:
$env:GEMINI_API_KEY = "your-key"
```

The app reads `GEMINI_API_KEY` (or `GOOGLE_API_KEY`) from the environment. It will also load those two names from a local `.env` if they are not already set. It never accepts `--api-key` on the command line, so the secret does not land in shell history.

## Install

Requires Node.js 20 or newer.

```powershell
npm install
npm run build
npm test
```

## Usage

```powershell
npx tsx src/cli.ts example_file.json
```

After a build:

```powershell
node dist/cli.js example_file.json
```

Useful flags:

```text
json-to-image example_file.json
json-to-image example_file.json --location small_house
json-to-image example_file.json --no-image
json-to-image example_file.scene.json
json-to-image example_file.json --all-images
json-to-image example_file.json --model gemini-3.1-flash-image
json-to-image example_file.json --verbose
```

Defaults:

- Compile **every** location into the scene file.
- Generate an image only for `initialLocationId` (here, `small_house`) so a first run is one API call.
- Skip image generation cleanly when no key is set. The scene file is still written.
- Image model: `gemini-2.5-flash-image` (Gemini native image / “Nano Banana”). Override with `--model`.

## Scene file shape

The scene file is pretty-printed JSON with a stable `kind` of `json-to-image-scene`. Each location becomes one scene with:

- `room` — interior vs exterior, size, floor, walls, implied window
- `camera` — stand / look walls, height, FOV
- `lights` — ambient fill plus sun
- `objects` — props, exits, and NPCs (appearance and visual state only)
- `prompt` — the exact text sent to Gemini

Dialogue, aliases, puzzle requirements, and other game-only fields are not copied into the scene or the prompt.

## Security

- Store keys in the environment or a gitignored `.env`. Never commit `.env`.
- Input files are capped at 2 MB and must be `.json`.
- Location IDs used in filenames may only contain letters, digits, `_`, and `-`.
- Companion files are always written in the same directory as the input.
- Gemini is sent only visual scene text, not NPC dialogue or item-requirement copy.
